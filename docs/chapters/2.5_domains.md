## Domains {#sec:domains} 
The top-level component `domains` contains an array of domains giving information on the ranges of parameters and variables in struct format. Within a specified domain, the corresponding model is expected to yield valid values. Each domain must contain a `name` and a `type` although right now only the `product_domain` type is supported, even though others like e. g.&nbsp;a simplex domain might be added later. A domain consists of the following components: 

-   `name`: custom string 
-   `type`: `product_domain` 
-   `axes`: array of parameters and variables in this domain in terms of individual axes. These can be continuous or categorical, mirroring the axis types defined in [Axis Specifications](#sec:axes){reference-type="ref" reference="sec:axes"}.
    -   A continuous axis has the components:  
        -   `name`: custom string
        -   `max`: ([optional]{.smallcaps}) upper bound of range. If absent, the range is unbounded from above ($+\infty$), unless `edges` is present.
        -   `min`: ([optional]{.smallcaps}) lower bound of range. If absent, the range is unbounded from below ($-\infty$), unless `edges` is present.
        -   `nbins`: ([optional]{.smallcaps}) number of equal-width bins of the default binning of this parameter or variable
        -   `edges`: ([optional]{.smallcaps}) array of bin boundaries of the default binning of this parameter or variable
    -   A categorical axis has the components: 
        - `name`: custom string
        - `categories`: array of unique strings enumerating the allowed values
    -   A fixed axis has the components: 
        - `name`: custom string
        - `value`: number, the single value of this parameter

An axis is categorical if it contains the component `categories`, fixed if it contains the component `value`, and continuous otherwise. A fixed axis [must not]{.smallcaps} contain `min`, `max`, `nbins`, `edges` or `categories`. A continuous axis [should]{.smallcaps} contain at least one of `min`, `max` and `edges`. An axis with none of these is valid and places no restriction on the range of the parameter; it still counts as listing the parameter in the domain (see [Analyses](#sec:analyses){reference-type="ref" reference="sec:analyses"}). Since JSON has no literal for infinity, omitting a bound is the only way to express an unbounded range.

A parameter with a fixed axis always takes the given `value` and is not free. It need not appear in any parameter point; a parameter point that is used with this domain and assigns it a different value is invalid (see [Parameter points](#sec:parameterpoints){reference-type="ref" reference="sec:parameterpoints"}).

The components `nbins` and `edges` specify a default binning, e.g. for plotting or for binned evaluation by an implementation that requires one. They have the same meaning and are subject to the same constraints as on binned axes (see [Binned Axes](#sec:axes-binned){reference-type="ref" reference="sec:axes-binned"}): `nbins` and `edges` [must not]{.smallcaps} both be present. `nbins` requires both `min` and `max` to be present. With `edges`, the first and last entries are the lower and upper bounds of the range, and `min` and `max` [must not]{.smallcaps} be present. Categorical axes [must not]{.smallcaps} carry `nbins` or `edges`.

```json title="Example: Domains"
"domains":[ 
  { 
    "name":"domain1", 
    "type":"product_domain", 
    "axes": [ 
      { "name" : "par_1", "min" : 1, "max" : 8 }, 
      { "name" : "par_2", "min" : 4.78, "max" : 6 }, 
      { "name" : "par_3", "value" : 0 }, 
      { "name" : "obs_x", "min" : 0, "max" : 10, "nbins" : 20 }, 
      { "name" : "obs_y", "edges" : [0, 1, 2, 5, 10] }, 
      { "name" : "channel", "categories": ["SR","CR"] }, 
      ... 
    ] 
  }, 
  ... 
]
```
