## HistFactory {#sec:histfactory}

HistFactory, documented by Cranmer et al. in 2012 [@hf], models bin counts as independent Poisson random variables whose expectations come from a mixture of histogram templates. Its random variables are the counts $n_i$; $x$ is the observable (or tuple of observables) used to define the fixed bins $B_i$.

A *channel* is a selected event category or analysis region with its own observed histogram, such as a signal or background control region. Each prediction adds the contributions of *samples* (signal and background processes) sharing the channel's binning. Parameter variations change yields, not bin boundaries; different channels may use different binning.

The sample yields and normalized shapes define the event intensity:

$$
\rho(x;\theta)=\sum_s N_s(\theta)f_s(x;\theta),
\qquad \int f_s(x;\theta)\,dx=1,
\qquad \lambda_i(\theta)=\int_{B_i}\rho(x;\theta)\,dx.
$$

Each sample has a yield $N_s$ and a normalized shape $f_s$ over the channel's observable region. The intensity integrates to the total expected yield $\sum_s N_s$, rather than to one. HistFactory stores bin yields directly; the decomposition into yields and normalized shapes is explanatory. The parameters $\theta$ may include both parameters of interest, such as a signal strength, and nuisance parameters describing uncertainties.

The function `histfactory` evaluates the expected bin yields $\lambda_i(\theta)$. The distribution `histfactory_dist` additionally specifies the observation model

$$
P(\mathbf{n}\mid\theta)=\prod_i\operatorname{Pois}(n_i\mid\lambda_i(\theta)),
\qquad n_i\in\{0,1,2,\ldots\},
$$

normalized over count vectors. For non-integer counts, such as those of an Asimov data set, each factor is evaluated as the continuous Poisson distribution `poisson_continuous_dist` (see [Continuous Poisson distribution](#dist:poisson-continuous){reference-type="ref" reference="dist:poisson-continuous"}) instead. Independence and Poisson fluctuations are modeling assumptions beyond the expected-yield prediction. Both representations use the samples, modifiers and constraint terms described below; their `type` entries differ. Figure [1](#fig:hf-example){reference-type="ref" reference="fig:hf-example"} illustrates the sample contributions. The figure is reproduced from [@atlashzz], © CERN for the benefit of the ATLAS Collaboration, licensed under CC BY 4.0; it is not covered by the CC0 dedication of this document.

![A binned statistical model describing a High Energy Physics measurement, in this case of the $H\rightarrow 4l$ process by the ATLAS collaboration. Three different sample (blue, red, violet) are considered.](/images/hf-example.png){#fig:hf-example width="60%"} 

In the modifier formula below, $\lambda(x)$ is a step function whose value in $B_i$ is the bin yield $\lambda_i(\theta)$. For continuous bins of width or volume $|B_i|$, the corresponding piecewise-constant intensity is $\rho(x;\theta)=\lambda_i(\theta)/|B_i|$; integrating $\lambda(x)$ itself would incorrectly introduce a bin-volume factor.

$$
\begin{aligned} \lambda(x)=\sum_{s\in\text{samples}} \left[ \left( d_s(x) + \sum_{\delta\in M_{\delta,s}} \delta(x,\theta_\delta) \right) \prod_{\kappa\in M_{\kappa,s}} \kappa(x,\theta_\kappa)   \right] \end{aligned} 
$$



Here $d_s(x)$ is the prediction associated with the sample $s$, a step function 



$$
\begin{aligned} d_s(x) = \chi^{y_s}_{b}(x) \end{aligned} 
$$



In this section, $\chi^{y_s}_{b}(x)$ denotes a generic step function in the binning $b$ such that $\chi^{y_s}_{b}(x) = y_{s,i}$, some constant, if $x\in B_i$. The $y_{s,i}$ in this case are the bin contents (yields) of the histograms. 
The $M_{\kappa,s}$ are the multiplicative modifiers of the sample $s$, the $M_{\delta,s}$ its additive modifiers. Each of the modifiers is either multiplicative ($\kappa$) or additive ($\delta$). All samples and modifiers share the same binning $b$. 
The modifiers depend on the model parameters $\theta$. Each modifier depends on a single parameter or, for the bin-wise types, on one parameter per bin; a `custom` modifier depends on the parameters of its function. The same parameter can be shared by several modifiers. By convention, parameters are denoted $\alpha$ if they affect all bins in a correlated way, and $\gamma$ if they affect only one bin at a time. The types of modifiers are

-   A *shape factor* or `shapefactor` modifier is a multiplicative modifier that scales each single bin by the value of an independent parameter $\gamma$. The parameters are $\gamma_1,\ldots,\gamma_n$, one for each of the $n$ bins in this region, and `parameters` holds one entry per bin. The parameters are constrained by the distributions named in `constraints`, if given, and free otherwise; individual entries of `constraints` [may]{.smallcaps} be `null`.
-   `shapesys` is a deprecated alias of `shapefactor`. Documents conforming to version 0.3 or later of this standard [should not]{.smallcaps} use it. Documents conforming to earlier versions may contain `shapesys` modifiers with bin-wise values in `data.vals` and a constraint type in `constraint`; implementations [should]{.smallcaps} read these according to the version of the standard the document conforms to, as given by `hs3_version` in its metadata.
-   A *correlated shape systematic* or `histosys` modifier changes the bin contents of the sample as a function of a single parameter $\alpha$. The modifier contains a `data` section with the subsections `hi` and `lo`, each of which contains `contents`: the full varied bin contents of the sample at $\alpha=+1$ and at $\alpha=-1$, respectively. These are not differences to the nominal bin contents. The response for intermediate and outlying $\alpha$ is set by the `interpolation` component, described below: in each bin $i$ it is the response function $I$ for the triplet $(y_-, y_0, y_+) = (\texttt{lo}_i, y_{s,i}, \texttt{hi}_i)$. With the interpolation type `add`, which is the usual choice, the modifier is additive, $\delta = I$; with the type `mult` it is multiplicative, $\kappa = I$. 
-   A *normalization systematic* or `normsys` modifier is a multiplicative modifier that scales the entire sample with the same factor $f$ that is a function of a single parameter $\alpha$. The modifier contains a `data` section with the values `hi` and `lo`, the factors at $\alpha=+1$ and $\alpha=-1$: $f(\alpha=0)=1$, $f(\alpha=+1)=$`hi` and $f(\alpha=-1)=$`lo`. The form of $f$ for intermediate and outlying $\alpha$ is set by the `interpolation` component, described below, with the triplet $(y_-, y_0, y_+) = (\texttt{lo}, 1, \texttt{hi})$: $f = I$ for the interpolation type `mult` and $f = 1 + I$ for the type `add`. 
-   A *normalization factor* or `normfactor` modifier is a multiplicative modifier that scales the entire sample in this region with the value of a single parameter $\mu$ itself. 
-   The `staterror` modifier encodes uncorrelated statistical uncertainties on the values of the step-functions, using a variant[^1] of the Barlow-Beeston Method [@barlowbeeston]. It is evaluated exactly like a `shapefactor`: $\gamma_i$ scales the bin $i$, and the parameters are constrained by the distributions named in `constraints`. These are authoritative. An implementation reading a document [must not]{.smallcaps} derive the constraint of a $\gamma_i$, or whether a $\gamma_i$ is fixed, from the `errors` of the samples; it [may]{.smallcaps} warn if the `errors` and the named constraints disagree significantly. The parameters $\vec{\gamma}$ are shared by all samples of the region that carry a `staterror` modifier.

    The following is guidance for writing such a modifier; the `errors` of the samples document where the numbers come from. The relative uncertainty of the bin $i$ [should]{.smallcaps} be $\delta_i=\sqrt{\sum_s \sigma_{s,i}^2}\,/\sum_s y_{s,i}$, with $y_{s,i}$ and $\sigma_{s,i}$ the `contents` and `errors` of all samples in this region carrying a `staterror` modifier. A sample without `errors` contributes its yield to the denominator and nothing to the numerator. In a bin without uncertainty ($\delta_i=0$) and in a bin without yield ($\sum_s y_{s,i}=0$, where $\delta_i$ is not defined), $\gamma_i$ [should]{.smallcaps} be fixed to 1, by a fixed axis in the domain or as `const` in the parameter points, and its entry in `constraints` [should]{.smallcaps} be `null`. The distributions named in `constraints` for the remaining bins [should]{.smallcaps} all be one and the same [Array distribution](#sec:array-distribution){reference-type="ref" reference="sec:array-distribution"} with one component per constrained bin, so that the same name is repeated for every constrained $\gamma_i$. Its `component_type` [should]{.smallcaps} be `gaussian_dist`; the alternative form is described below. The component for the bin $i$ takes the form
    -   for `component_type` `gaussian_dist`: `mean` is $\gamma_i$, `sigma` is $\delta_i$, and `x` is a name whose value is 1. This is the treatment of pyhf;
    -   for `component_type` `poisson_continuous_dist`: `mean` is $\gamma_i\tau_i$, for instance a `product` function of $\gamma_i$ and the constant $\tau_i=\delta_i^{-2}$, and `x` is a name whose value is $\tau_i$. This is the Barlow-Beeston-lite form and the default of ROOT's HistFactory, which versions of this standard before 0.3 encoded as a `barlow_beeston_lite_poisson_constraint_dist`; that type has been removed. Since $\tau_i$ is in general not an integer, the component type is the continuous Poisson distribution `poisson_continuous_dist` (see [Continuous Poisson distribution](#dist:poisson-continuous){reference-type="ref" reference="dist:poisson-continuous"}), not the discrete `poisson_dist`.

-   A `custom` modifier is a multiplicative modifier that scales the sample with the value of an arbitrary function $f$ defined in the top-level component `functions` (see [Functions](#sec:functions)). The `name` of the modifier is the name of $f$. If $f$ depends on the observables, it acts as a shape factor, otherwise as a normalization factor. Its parameters are the parameters of $f$; the components `parameters`, `data` and `constraints` are not used for this type. 

The different modifiers and their descriptions are also summarized in the following table: 

| **Type of Modifier**         | **Description**               | **Definition**                               | **Free Parameters**           | **Number of Free Parameters** |
|------------------------------|-------------------------------|----------------------------------------------|-------------------------------|--------------------------------|
| `histosys`                   | Correlated Shape systematic   | $\delta(x,\alpha) = I(\alpha; \chi_b^{\text{lo}}, \chi_b^{y_s}, \chi_b^{\text{hi}})$ | $\alpha$      | 1                              |
| `normsys`                    | Normalization systematic      | $\kappa(x,\alpha) = f(\alpha)$               | $\alpha$                      | 1                              |
| `normfactor`                 | Normalization factor          | $\kappa(x,\mu) = \mu$                        | $\mu$                         | 1                              |
| `shapefactor`, `staterror`   | Shape factor                  | $\kappa(x,\vec{\gamma}) = \chi_b^{\gamma}$   | $\gamma_1$, ..., $\gamma_n$   | #bins                          |
| `custom`                     | Custom function               | $\kappa(x,\vec{\theta}) = f(x,\vec{\theta})$ | parameters of $f$             | #parameters of $f$             |


The way modifiers affect the yield in the corresponding bin is subject to an interpolation function. The `histosys` and `normsys` modifiers thus allow for an additional component `interpolation`, a struct with the components 

-   `type`: how the response combines with the sample prediction, `add` or `mult`, for additive or multiplicative, respectively, 
-   `in`: the interpolating function used inside the bounds, $|\theta|<1$, 
-   `out`: the extrapolating function used outside the bounds, $|\theta|\geq1$, if `null` the same function as for interpolation is used.

The response of a modifier to its parameter $\theta$ is described by a response function $I(\theta; y_-, y_0, y_+)$, where $y_0$ is the nominal value and $y_-$ and $y_+$ are the values at $\theta=-1$ and $\theta=+1$. For a `histosys` modifier these are, bin by bin, the nominal contents of the sample and the `lo` and `hi` contents; for a `normsys` modifier, $y_0=1$ and $y_\mp$ are the factors `lo` and `hi`. The final modified prediction $y(\theta_1,\dots,\theta_n)$ is obtained by combining the nominal value $y_0$ with the response functions of all parameters $\theta_i$. Unlike $y$, $I$ is anchored relative to $y_0$, with the anchor values depending on the combination `type`:

- For `type="add"`: $I(0) = 0$, $I(+1) = y_+ - y_0$, $I(-1) = y_- - y_0$
- For `type="mult"`: $I(0) = 1$, $I(+1) = y_+ / y_0$, $I(-1) = y_- / y_0$

For `type="mult"`, the combined prediction follows as:

$$
y(\theta_1,\dots,\theta_n) = y_0 \cdot \prod_i I(\theta_i; y_{i,-}, y_0, y_{i,+}),
$$

while for `type="add"` the combination follows as:

$$
y(\theta_1,\dots,\theta_n) = y_0 + \sum_i I(\theta_i; y_{i,-}, y_0, y_{i,+}).
$$

Here $y_{i,-}$ and $y_{i,+}$ denote the `lo`/`hi` variations associated with parameter $\theta_i$, and $y_0$ the nominal value, which is shared across all parameters. $I$ depends on $y_0$ only through the differences $y_\pm - y_0$ for `type="add"`, and only through the ratios $y_\pm/y_0$ for `type="mult"`.

The `type` describes how the response is anchored and combined, not the kind of modifier: every combination of `type`, `in` and `out` that is defined by the rule below is valid for `histosys` and for `normsys` modifiers alike. In the modifier formula above, a response with `type="add"` on a `histosys` modifier is an additive modifier $\delta = I$ and a response with `type="mult"` a multiplicative modifier $\kappa = I$. For a `normsys` modifier, where $y_0=1$, the factor is $\kappa = I$ for `type="mult"` and $\kappa = 1 + I$ for `type="add"`. One `default_interpolation` can therefore serve a channel with modifiers of both kinds.

The following functions are allowed for `in` and `out`:

- `poly1`: linear function $c_0 + c_1\theta$, with two parameters
- `poly2`: parabolic function $c_0 + c_1\theta + c_2\theta^2$, with three parameters
- `poly6`: degree-6 polynomial $\sum_{k=0}^{6} c_k\theta^k$, with seven parameters
- `exp`: exponential function $a\,e^{b\theta}$, with two parameters

Every combination of `type`, `in` and `out` defines the response function by the following rule, which fixes all parameters of the chosen functions:

1.  The anchors $I(0)$ and $I(\pm 1)$ are given by `type`, as stated above.
2.  For `poly1` and `exp`, the `in` function consists of two pieces, one for $-1\leq\theta<0$ and one for $0\leq\theta\leq 1$. Each piece passes through $I(0)$ and through the anchor at its own end. For `poly2` and `poly6`, the `in` function is a single function on $|\theta|\leq 1$ that passes through all three anchors.
3.  The `out` function is one function of the given kind for $\theta>1$ and another one for $\theta<-1$. If `out` is `null`, the `in` function, or its piece on the respective side, is continued beyond $|\theta|=1$.
4.  `poly6` as `in` function carries a defining property: it is the degree-6 polynomial for which the `out` function of either side, continued to $\theta=0$, takes the value $I(0)$. For `out: poly1` this means that the tangents at $\theta=\pm 1$ pass through the point $(0, I(0))$.
5.  The parameters that are still free are fixed by requiring continuity at $\theta=\pm 1$ of the value, of the first derivative $\frac{\mathrm{d}I}{\mathrm{d}\theta}$ and of the second derivative $\frac{\mathrm{d}^2I}{\mathrm{d}\theta^2}$, applied in this order until no free parameter is left.

If parameters are left free after the last step, or if the conditions have no solution, the combination is not defined and a document using it is invalid. This is the case, for example, for `poly6` as `out` function, and for `exp` as `in` function with `type="add"`, since an exponential cannot pass through $I(0)=0$. An implementation [must]{.smallcaps} reject a combination that it cannot evaluate and [must not]{.smallcaps} substitute another one.



The following six combinations are in common use. They are worked examples of the rule above, not an exhaustive list of the valid combinations. Note that for `type="mult"`, all interior and extrapolation terms are expressed as ratios $y_\pm/y_0$ rather than raw $y_\pm$, so that the anchor condition $I(0)=1$ holds independent of $y_0$; for `type="add"`, terms are expressed as differences $y_\pm - y_0$, consistent with the anchor $I(0)=0$.

- additive, piecewise linear: 
    - `{"type":"add", "in":"poly1", "out":null}`
    - with $I_1(\theta; y_-, y_0, y_+) = \left\{ \begin{array}{ll} \theta\cdot(y_+ - y_0) &  \theta\geq0 \\ \theta\cdot(y_0-y_-) &  \theta<0\end{array}\right.$
- multiplicative, piecewise exponential: 
    - `{"type":"mult", "in":"exp", "out":null}`
    - with $I_2(\theta; y_-, y_0, y_+) = \left\{ \begin{array}{ll} (y_+/y_0)^\theta &  \theta\geq0 \\ (y_-/y_0)^{-\theta} &  \theta<0 \end{array}\right.$
- additive, quadratic interpolation and linear extrapolation 
    - `{"type":"add", "in":"poly2", "out":"poly1"}`
    - with $I_3(\theta; y_-, y_0, y_+) = \left\{\begin{array}{ll}(2s+d)\cdot(\theta - 1) + y_+ - y_0 &  \theta > 1 \\ s\cdot\theta^2 +d\cdot\theta & |\theta|\leq 1 \\ -(2s-d)\cdot(\theta + 1) + y_- - y_0& \theta < -1\end{array}\right.$,
  where $s=\tfrac12(y_+ + y_-) - y_0$ and $d=\tfrac12 (y_+ - y_-)$
- additive, polynomial (6th degree) interpolation and linear extrapolation 
    - `{"type":"add", "in":"poly6", "out":"poly1"}`
    - with $I_4(\theta; y_-, y_0, y_+) = \left\{\begin{array}{ll} \theta\cdot(y_+ - y_0) & \theta \geq 1 \\ \theta\cdot(S+\theta \cdot A (15+\theta^2\cdot(3\theta^2 -10))) & |\theta| < 1 \\ \theta\cdot(y_0 - y_-) & \theta \leq -1 \end{array}\right.$,
  where $S=\tfrac12(y_+ - y_-)$ and $A=\tfrac{1}{16}(y_+ + y_- -2y_0)$
- multiplicative, polynomial (6th degree) interpolation and exponential extrapolation
    - `{"type":"mult", "in":"poly6", "out":"exp"}`
    - with $I_5(\theta; y_-, y_0, y_+) = \left\{\begin{array}{ll} (y_+/y_0)^\theta &  \theta\geq 1 \\ 1+\theta\cdot(a+\theta\cdot(b+\theta\cdot(c+\theta\cdot(d+\theta\cdot(e+\theta\cdot f)))))& |\theta|<1\\ (y_-/y_0)^{-\theta} &  \theta\leq-1\end{array}\right.$,
    where:
    $\begin{array}{l}
    a=\tfrac18(15A_0-7S_1+A_2) \\
    b=\tfrac18(-24+24S_0-9A_1+S_2) \\
    c=\tfrac14(-5A_0+5S_1-A_2) \\
    d=\tfrac14(12-12S_0+7A_1-S_2) \\
    e=\tfrac18(3A_0-3S_1+A_2) \\
    f=\tfrac18(-8+8S_0-5A_1+S_2)
    \end{array}$,
    with $u=y_+/y_0$, $v=y_-/y_0$, $\log t := \begin{cases}\log t & t>0\\0 & t\leq0\end{cases}$, and
    $\begin{array}{l}
    S_0=\tfrac12(u+v) \quad A_0=\tfrac12(u-v) \\
    S_1=\tfrac12(u\log u-v\log v) \quad A_1=\tfrac12(u\log u+v\log v) \\
    S_2=\tfrac12(u\log^2 u+v\log^2 v) \quad A_2=\tfrac12(u\log^2 u-v\log^2 v)
    \end{array}$
- multiplicative, polynomial (6th degree) interpolation and linear extrapolation 
    - `{"type":"mult", "in":"poly6", "out":"poly1"}`
    - with $I_6(\theta; y_-, y_0, y_+) = 1 + I_4(\theta; y_-/y_0, 1, y_+/y_0)$

Modifiers can be constrained. This is indicated by the component `constraints`, which names one or more distributions defined in the top-level component `distributions`. These are typically of type `gaussian_dist` or `poisson_continuous_dist`, but any distribution type is allowed. The auxiliary observation of a Poisson constraint term is in general not an integer, so such terms use the continuous Poisson distribution `poisson_continuous_dist` (see [Continuous Poisson distribution](#dist:poisson-continuous){reference-type="ref" reference="dist:poisson-continuous"}), not the discrete `poisson_dist`. In essence, the likelihood picks up a penalty term for changing a constrained parameter too far away from its nominal value. By convention, the nominal value is 0 for the parameters of `histosys` and `normsys` modifiers and 1 for those of all other types. Constraints on `histosys` and `normsys` parameters [should]{.smallcaps} be a `gaussian_dist` with the parameter $\alpha$ as `mean`, a `sigma` of 1 and an `x` whose value is 0, such that $\alpha=\pm1$ corresponds to the `hi` and `lo` variations. As for the `staterror` constraints above, `x` holds the auxiliary observation and `mean` the parameter. 

The component `constraints` of a modifier states a requirement and adds no term to the likelihood. Every likelihood that contains the prediction, i.e. that contains a `histfactory_dist` or a distribution that depends on a `histfactory` function, [must]{.smallcaps} have each distribution named in `constraints` contribute a factor exactly once: the distribution is listed in `aux_distributions`, or it is listed in `distributions`, or it is reached from one of these as a factor of a `product_dist` or as a component of a `combined_dist` that is paired with a sub-data set. For a pure model (see [Pure models](#sec:likelihood-pure-model){reference-type="ref" reference="sec:likelihood-pure-model"}), which has no data and no terms to evaluate, the requirement is that each such distribution is listed in one of these ways, where every component of a `combined_dist` counts. The terms of a likelihood are composed with union composition (see [Composition of factors](#sec:composition){reference-type="ref" reference="sec:composition"}). A distribution that is reached in several ways through union composition, that is, by being listed in `distributions` or `aux_distributions`, as a component of a `combined_dist` or as a component of an `array_dist`, or under several names that refer to identical distributions (see [Identity](#sec:identity){reference-type="ref" reference="sec:identity"}), contributes once. A distribution that is reached as a factor of a product distribution contributes through that product, which is a single factor of the likelihood, and [must not]{.smallcaps} be reached in any other way. A document that contains a likelihood for which this is not the case is invalid. Implementations [must not]{.smallcaps} add constraint terms that the likelihood does not list. Where the names in a constraint take their values from is described in [Likelihoods](#sec:likelihoods){reference-type="ref" reference="sec:likelihoods"}. 

A distribution may be named in `constraints` for several parameters, for example for all parameters of a modifier, or in several modifiers, samples or channels. This is how a single distribution covering several parameters, such as an [Array distribution](#sec:array-distribution){reference-type="ref" reference="sec:array-distribution"}, is attached to all of them. This does not change the requirement: however many times it is named, such a distribution contributes to the likelihood exactly once. 

The components of a HistFactory prediction are: 
    
-   `name`: custom unique string 
-   `type`: `histfactory` (function) or `histfactory_dist` (distribution) 
-   `axes`: array of binned axis structs as defined for binned data in [Axis Specifications](#sec:axes). Bin-wise quantities such as bin weights are stored as one-dimensional arrays with one entry per bin of the (possibly multi-dimensional) binning, ordered as defined in [Flattening of Binned Contents](#sec:axes-flattening){reference-type="ref" reference="sec:axes-flattening"}. This applies to the `contents` and `errors` of the samples as well as to all bin-wise data of the modifiers. 
-   `default_interpolation`: [optional]{.smallcaps} struct defining the default interpolation behaviour, for `histosys` and `normsys` modifiers that do not specify it on their own. It has the components `type`, `in` and `out`, as described above.
-   `samples`: array of structs containing the samples of this channel.     For details see below. 
Struct of one sample:  
    -   `name`: ([optional]{.smallcaps}) custom string, unique within this     function 
    -   `data`: struct containing the component `contents` and the ([optional]{.smallcaps}) component `errors`, depicting the sample contents and their per-bin uncertainties. Both components are arrays with length equal to the number of bins. If `errors` is absent, no per-bin uncertainty is associated with the sample. This `data` is the template of the sample, i.e. the predicted yields and their uncertainties, not observed data. 
    -   `modifiers`: array of structs with each struct containing the modifiers for this sample.
    Struct of one modifier:
        -  `name`: ([optional]{.smallcaps}) custom string, unique within this sample. [required]{.smallcaps} for `custom` modifiers, where it names a function defined in the top-level component `functions`.
        -  `type`: type of the modifier
        -  `parameters`: array of strings naming the parameters controlling this modifier. Not given for `custom` modifiers, whose parameters are those of the function.
        -  `data`: [optional]{.smallcaps} relevant data for modifier. Its format depends on `type`, which is described above.
        -  `constraints`: [optional]{.smallcaps} array of distribution names, with one entry for each parameter in `parameters`. Individual entries [may]{.smallcaps} be `null`, leaving the corresponding parameter unconstrained. 
        -  `interpolation`: [optional]{.smallcaps} struct, for `histosys` and `normsys` modifiers only, defining how the effect of the modifier is calculated within and outside of the boundaries $\theta=\pm 1$. It has the components `type`, `in` and `out` as described above. If it is omitted for at least one `histosys` or `normsys` modifier, the component `default_interpolation` of this distribution or function becomes [required]{.smallcaps}. Implementations [must not]{.smallcaps} assume a default interpolation of their own; a document in which a `histosys` or `normsys` modifier omits `interpolation` and no `default_interpolation` is given is invalid and [must]{.smallcaps} be rejected. Modifiers of other types have no interpolation.

For modifiers controlling a single parameter (`histosys`, `normsys`, `normfactor`), the array `parameters` holds a single entry, and so does `constraints` when present. 

Modifiers that share a parameter, as indicated by `parameters`, are fully correlated through it. They [must]{.smallcaps} name the same constraint term in `constraints`. Like any constraint, that term contributes to the likelihood once.

A likelihood that uses this channel has to list the constraints named by its modifiers, for example in `aux_distributions`:

The `staterror` constraint named above is a single array, defined as one entry of the top-level `distributions`. For illustration, assuming that `mySignal` is the only sample, so that $\delta_i=\sigma_{s,i}/y_{s,i}$, and with `nom_gamma_stat_1` and `nom_gamma_stat_2` being constant parameters of value 1:

```json title="Constraint of the staterror modifier"
{
  "distributions": [
    {
      "name": "gamma_stat_constraints",
      "type": "array_dist",
      "component_type": "gaussian_dist",
      "components": [
        { "x": "nom_gamma_stat_1", "mean": "gamma_stat_1", "sigma": 0.2 },
        { "x": "nom_gamma_stat_2", "mean": "gamma_stat_2", "sigma": 0.143 }
      ]
    }
  ]
}
```

[^1]: The variation consists of summarizing all contributions in the     stack to a single contribution as far as treatment of the     statistical uncertainties is concerned.
