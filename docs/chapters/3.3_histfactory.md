## HistFactory {#sec:histfactory}

HistFactory, documented by Cranmer et al. in 2012 [@hf], models bin counts as independent Poisson random variables whose expectations come from a mixture of histogram templates. Its random variables are the counts $n_i$; $x$ is the observable (or tuple of observables) used to define the fixed bins $B_i$.

A *channel* is a selected event category or analysis region with its own observed histogram, such as a signal or background control region. Each prediction adds the contributions of *samples* (signal and background processes) sharing the channel's binning. Parameter variations change yields, not bin boundaries; different channels may use different binning.

The sample yields and normalized shapes define the event intensity:

$$
\rho(x;\theta)=\sum_s N_s(\theta)f_s(x;\theta),
\qquad \int f_s(x;\theta)\,dx=1,
\qquad \lambda_i(\theta)=\int_{B_i}\rho(x;\theta)\,dx.
$$

Each sample has a yield $N_s$ and a normalized shape $f_s$ over the channel's observable region. The intensity integrates to the total expected yield $\sum_s N_s$, rather than to one. HistFactory stores bin yields directly; the decomposition into yields and normalized shapes is explanatory. The parameters $\theta$ may include both parameters of interest, such as a signal strength, and nuisance parameters describing uncertainties.

The function `histfactory` evaluates the expected bin yields $\lambda_i(\theta)$. The distribution `histfactory_dist` additionally specifies the observation model

$$
P(\mathbf{n}\mid\theta)=\prod_i\operatorname{Pois}(n_i\mid\lambda_i(\theta)),
\qquad n_i\in\{0,1,2,\ldots\},
$$

normalized over count vectors. Independence and Poisson fluctuations are modeling assumptions beyond the expected-yield prediction. Both representations use the samples, modifiers and constraint terms described below; their `type` entries differ. Figure [1](#fig:hf-example){reference-type="ref" reference="fig:hf-example"} illustrates the sample contributions (originally from [@atlashzz]).

![A binned statistical model describing a High Energy Physics measurement, in this case of the $H\rightarrow 4l$ process by the ATLAS collaboration. Three different sample (blue, red, violet) are considered.](/images/hf-example.png){#fig:hf-example width="60%"} 

In the modifier formula below, $\lambda(x)$ is a step function whose value in $B_i$ is the bin yield $\lambda_i(\theta)$. For continuous bins of width or volume $|B_i|$, the corresponding piecewise-constant intensity is $\rho(x;\theta)=\lambda_i(\theta)/|B_i|$; integrating $\lambda(x)$ itself would incorrectly introduce a bin-volume factor.

$$
\begin{aligned} \lambda(x)=\sum_{s\in\text{samples}} \left[ \left( d_s(x) + \sum_{\delta\in M_{\delta}} \delta(x,\theta_\delta) \right) \prod_{\kappa\in M_\kappa} \kappa(x,\theta_\kappa)   \right] \end{aligned} 
$$



Here $d_s(x)$ is the prediction associated with the sample $s$, a step function 



$$
\begin{aligned} d_s(x) = \chi^{y_s}_{b}(x) \end{aligned} 
$$



In this section, $\chi^{y_s}_{b}(x)$ denotes a generic step function in the binning $b$ such that $\chi_{b}(x) = y_{s,i}$, some constant, if $x\in[b_i,b_{i+1})$. The $y_{s,i}$ in this case are the bin contents (yields) of the histograms. 
The $M_\kappa$ are the multiplicative modifiers, the $M_\delta$ are the additive modifiers. Each of the modifiers is either multiplicative ($\kappa$) or additive ($\delta$). All samples and modifiers share the same binning $b$. 
The modifiers depend on the model parameters $\theta$. Each modifier can only depend on one $\theta_i$, but the $\theta_i$ can take the form of vectors and the same $\theta_i$ can be shared by several modifiers. By convention, these are denoted $\alpha$ if they affect all bins in a correlated way, and $\gamma$ if they affect only one bin at a time. The types of modifiers are

-   A *shape factor* or `shapefactor` modifier is a multiplicative modifier that scales each single bin by the value of an independent parameter $\gamma$. Here, $\theta_i=\vec{\gamma}$, where the length of $\vec{\gamma}$ is equal to the number of bins in this region, and `parameters` holds one entry per bin. The parameters are constrained by the distributions named in `constraints`, if given, and free otherwise; individual entries of `constraints` [may]{.smallcaps} be `null`.
-   `shapesys` is a deprecated alias of `shapefactor`. Documents conforming to version 0.3 or later of this standard [should not]{.smallcaps} use it. Documents conforming to earlier versions may contain `shapesys` modifiers with bin-wise values in `data.vals` and a constraint type in `constraint`; implementations [should]{.smallcaps} read these according to the version of the standard the document conforms to, as given by `hs3_version` in its metadata.
-   A *correlated shape systematic* or `histosys` modifier is an     additive modifier that adds or subtracts a constant step function     $\chi^f$, scaled with a single factor $\alpha$. The modifier     contains a `data` section, which contains the subsections     $\texttt{hi}$ and $\texttt{lo}$ that help to define the step     function $\chi^f$. They contain `contents`, which define the     bin-wise additions or subtractions for $\alpha=1$. The functional form of $\chi^f$ for intermediate and outlying $\alpha$ is set by the `interpolation` component, described below. Here,     $\theta_i=\alpha$. 
-   A *normalization systematic* or `normsys` modifier is a     multiplicative modifier that scales the entire sample with the same     constant factor $f$ that is a function of $\alpha$. The modifier     contains a `data` section, which contains the values $\texttt{hi}$     and $\texttt{lo}$ that help to define $f$. There are different     functional forms that can be chosen for $f$. However, by convention     $f(\alpha=0)=1$, $f(\alpha=+1)=$"`hi`" and     $f(\alpha=-1)=$"`lo`". The functional form of $f$ for intermediate and outlying $\alpha$ is set by the `interpolation` component, described below. In this case, $\theta_i=\alpha$. 
-   A *normalization factor* or `normfactor` modifier is a     multiplicative modifier that scales the entire sample in this region     with the value of the parameter $\mu$ itself. In this case,     $\theta_i=\mu$. 
-   The `staterror` modifier is a shorthand for encoding uncorrelated statistical uncertainties on the values of the step-functions, using a variant[^1] of the Barlow-Beeston Method [@barlowbeeston]. It acts as a `shapefactor` whose per-bin relative uncertainty is derived from the samples: $\delta_i=\sqrt{\sum_s \sigma_{s,i}^2}\,/\sum_s y_{s,i}$, with $y_{s,i}$ and $\sigma_{s,i}$ the `contents` and `errors` of all samples in this region carrying a `staterror` modifier. The distributions named in `constraints` [should]{.smallcaps} all be one and the same [Array distribution](#sec:array-distribution){reference-type="ref" reference="sec:array-distribution"} with one component per bin $i$, so that the same name is repeated for every $\gamma_i$. By the rule on repeated constraints below, it enters the likelihood once. Its `component_type` [should]{.smallcaps} be `gaussian_dist`; the alternative form is described below. Its parameters $\vec{\gamma}$ are shared by all samples of the region that carry a `staterror` modifier. The component $i$ takes the form
    -   for `component_type` `gaussian_dist`: `mean` is $\gamma_i$, `sigma` is $\delta_i$, and `x` is a global observable with nominal value 1. This is the default of ROOT's HistFactory and the treatment of pyhf;
    -   for `component_type` `poisson_dist`: `mean` is $\gamma_i\tau_i$, for instance a `product` function of $\gamma_i$ and the constant $\tau_i=\delta_i^{-2}$, and `x` is a global observable with nominal value $\tau_i$. This is the Barlow-Beeston-lite form. Since $\tau_i$ is in general not an integer, it relies on `poisson_dist` being evaluated at non-integer `x`.

    The global observables named by `x` are provided as an `unbinned` data set with one axis per component and a single entry holding the nominal values, as described in [Auxiliary measurements](#sec:aux-measurements){reference-type="ref" reference="sec:aux-measurements"}. 
-   A `custom` modifier is a multiplicative modifier that scales the sample with the value of an arbitrary function $f$ defined in the top-level component `functions` (see [Functions](#sec:functions)). The `name` of the modifier is the name of $f$. If $f$ depends on the observables, it acts as a shape factor, otherwise as a normalization factor. Here, $\theta_i$ are the parameters of $f$; the components `parameters`, `data` and `constraints` are not used for this type. 

The different modifiers and their descriptions are also summarized in the following table: 

| **Type of Modifier**         | **Description**               | **Definition**                               | **Free Parameters**           | **Number of Free Parameters** |
|------------------------------|-------------------------------|----------------------------------------------|-------------------------------|--------------------------------|
| `histosys`                   | Correlated Shape systematic   | $\delta(x,\alpha) = \alpha * \chi_b^f$       | $\alpha$                      | 1                              |
| `normsys`                    | Normalization systematic      | $\kappa(x,\alpha) = f(\alpha)$               | $\alpha$                      | 1                              |
| `normfactor`                 | Normalization factor          | $\kappa(x,\mu) = \mu$                        | $\mu$                         | 1                              |
| `shapefactor`, `staterror`   | Shape factor                  | $\kappa(x,\vec{\gamma}) = \chi_b^{\gamma}$   | $\gamma_0$, ..., $\gamma_n$   | #bins                          |
| `custom`                     | Custom function               | $\kappa(x,\vec{\theta}) = f(x,\vec{\theta})$ | parameters of $f$             | #parameters of $f$             |


The way modifiers affect the yield in the corresponding bin is subject to an interpolation function. The `histosys` and `normsys` modifiers thus allow for an additional component `interpolation`, a struct with the components 

-   `type`: how the response combines with the sample prediction, `add` or `mult`, for additive or multiplicative, respectively, 
-   `in`: the interpolating function used inside the bounds, $|\theta|<1$, 
-   `out`: the extrapolating function used outside the bounds, $|\theta|\geq1$, if `null` the same function as for interpolation is used.

The final modified prediction $y(\theta_1,\dots,\theta_n)$ is obtained by combining the sample's nominal prediction $y_0$ with a normalized response function $I(\theta; y_-, y_0, y_+)$ for each parameter $\theta_i$. Unlike $y$, $I$ is anchored relative to $y_0$ rather than to it directly, with the anchor values depending on the combination `type`:

- For `type="add"`: $I(0) = 0$, $I(+1) = y_+ - y_0$, $I(-1) = y_- - y_0$
- For `type="mult"`: $I(0) = 1$, $I(+1) = y_+ / y_0$, $I(-1) = y_- / y_0$

For `type="mult"`, the combined prediction follows as:

$$
y(\theta_1,\dots,\theta_n) = y_0 \cdot \prod_i I(\theta_i; y_{i,-}, y_0, y_{i,+}),
$$

while for `type="add"` the combination follows as:

$$
y(\theta_1,\dots,\theta_n) = y_0 + \sum_i I(\theta_i; y_{i,-}, y_0, y_{i,+}).
$$

Here $y_{i,-}$ and $y_{i,+}$ denote the `lo`/`hi` variations associated with parameter $\theta_i$; $y_0$, the sample's nominal prediction, is shared across all parameters and enters only through the combination above, never through $I$ itself.

The following functions are allowed for `in` and `out`:

- `poly1`: linear function
- `poly2`: parabolic function
- `poly6`: degree-6 polynomial
- `exp`: exponential function

The choice of functions for `in` and `out`, together with the anchor conditions above and, where required, matching of first and second derivatives at the boundary ($\left.\frac{\mathrm{d}I}{\mathrm{d}\theta}\right|_{\theta=\pm 1}$ and $\left.\frac{\mathrm{d}^2I}{\mathrm{d}\theta}\right|_{\theta=\pm 1}$), fixes all free parameters of the chosen functions except for $\theta$ itself. 


The following choices of $I$ are often used and showcase the resulting functional forms for common combinations of `type`, `in` and `out`. Note that for `type="mult"`, all interior and extrapolation terms are expressed as ratios $y_\pm/y_0$ rather than raw $y_\pm$, so that the anchor condition $I(0)=1$ holds independent of $y_0$; for `type="add"`, terms are expressed as differences $y_\pm - y_0$, consistent with the anchor $I(0)=0$.

- additive, piecewise linear: 
    - `{"type":"add", "in":"poly1", "out":null}`
    - with $I_1(\theta; y_-, y_0, y_+) = \left\{ \begin{array}{ll} \theta\cdot(y_+ - y_0) &  \theta\geq0 \\ \theta\cdot(y_0-y_-) &  \theta<0\end{array}\right.$
- multiplicative, piecewise exponential: 
    - `{"type":"mult", "in":"exp", "out":null}`
    - with $I_2(\theta; y_-, y_0, y_+) = \left\{ \begin{array}{ll} (y_+/y_0)^\theta &  \theta\geq0 \\ (y_-/y_0)^{-\theta} &  \theta<0 \end{array}\right.$
- additive, quadratic interpolation and linear extrapolation 
    - `{"type":"add", "in":"poly2", "out":"poly1"}`
    - with $I_3(\theta; y_-, y_0, y_+) = \left\{\begin{array}{ll}(2s+d)\cdot(\theta - 1) + y_+ - y_0 &  \theta > 1 \\ s\cdot\theta^2 +d\cdot\theta & |\theta|\leq 1 \\ -(2s-d)\cdot(\theta + 1) + y_- - y_0& \theta < -1\end{array}\right.$,
  where $s=\tfrac12(y_+ + y_-) - y_0$ and $d=\tfrac12 (y_+ - y_-)$
- additive, polynomial (6th degree) interpolation and linear extrapolation 
    - `{"type":"add", "in":"poly6", "out":"poly1"}`
    - with $I_4(\theta; y_-, y_0, y_+) = \left\{\begin{array}{ll} \theta\cdot(y_+ - y_0) & \theta \geq 1 \\ \theta\cdot(S+\theta \cdot A (15+\theta^2\cdot(3\theta^2 -10))) & |\theta| < 1 \\ \theta\cdot(y_0 - y_-) & \theta \leq -1 \end{array}\right.$,
  where $S=\tfrac12(y_+ - y_-)$ and $A=\tfrac{1}{16}(y_+ + y_- -2y_0)$
- multiplicative, polynomial (6th degree) interpolation and exponential extrapolation
    - `{"type":"mult", "in":"poly6", "out":"exp"}`
    - with $I_5(\theta; y_-, y_0, y_+) = \left\{\begin{array}{ll} (y_+/y_0)^\theta &  \theta\geq 1 \\ 1+\theta\cdot(a+\theta\cdot(b+\theta\cdot(c+\theta\cdot(d+\theta\cdot(e+\theta\cdot f)))))& |\theta|<1\\ (y_-/y_0)^{-\theta} &  \theta\leq-1\end{array}\right.$,
    where:
    $\begin{array}{l}

    b=\tfrac18(-24+24S_0-9A_1+S_2) \\
    c=\tfrac14(-5A_0+5S_1-A_2) \\
    d=\tfrac14(12-12S_0+7A_1-S_2) \\

    f=\tfrac18(-8+8S_0-5A_1+S_2)
    \end{array}$,

    $\begin{array}{l}
    S_0=\tfrac12(u+v) \quad A_0=\tfrac12(u-v) \\
    S_1=\tfrac12(u\log u-v\log v) \quad A_1=\tfrac12(u\log u+v\log v) \\
    S_2=\tfrac12(u\log^2 u+v\log^2 v) \quad A_2=\tfrac12(u\log^2 u-v\log^2 v)
    \end{array}$
- multiplicative, polynomial (6th degree) interpolation and linear extrapolation 
    - `{"type":"mult", "in":"poly6", "out":"poly1"}`
    - with $I_6(\theta; y_-, y_0, y_+) = 1 + I_4(\theta; y_-/y_0, 1, y_+/y_0)$

Modifiers can be constrained. This is indicated by the component `constraints`, which names one or more distributions defined in the top-level component `distributions`. These are typically of type `gaussian_dist` or `poisson_dist`, but any distribution type is allowed. In essence, the likelihood picks up a penalty term for changing a constrained parameter too far away from its nominal value. By convention, the nominal value is 0 for the parameters of `histosys` and `normsys` modifiers and 1 for those of all other types. Constraints on `histosys` and `normsys` parameters [should]{.smallcaps} be a `gaussian_dist` with `mean` 0 and `sigma` 1, such that $\alpha=\pm1$ corresponds to the `hi` and `lo` variations. 

A distribution may be named in `constraints` for several parameters, for example for all parameters of a modifier, or in several modifiers, samples or channels. This is how a single distribution covering several parameters, such as an [Array distribution](#sec:array-distribution){reference-type="ref" reference="sec:array-distribution"}, is attached to all of them. Such a distribution is identified by its name and enters the likelihood exactly once, however many times it is named. Implementations [must not]{.smallcaps} include a constraint term once per parameter or once per modifier that names it.

The constraint terms belong to the prediction and not to its representation: a likelihood that contains a `histfactory_dist`, or a distribution that depends on a `histfactory` function, considers the constraint terms of all modifiers of that prediction in addition to the `aux_likelihood` section of the likelihood, in the same way for both representations. 

The components of a HistFactory prediction are: 
    
-   `name`: custom unique string 
-   `type`: `histfactory` (function) or `histfactory_dist` (distribution) 
-   `axes`: array of binned axis structs as defined for binned data in [Axis Specifications](#sec:axes). 
-   `default_interpolation`: [optional]{.smallcaps} struct defining the default interpolation behaviour, for modifiers that do not specify it on their own. It has the components `type`, `in` and `out`, as described above.
-   `samples`: array of structs containing the samples of this channel.     For details see below. 
Struct of one sample:  
    -   `name`: ([optional]{.smallcaps}) custom string, unique within this     function 
    -   `data`: struct containing the component `contents` and the ([optional]{.smallcaps}) component `errors`, depicting the sample contents and their per-bin uncertainties. Both components are arrays with length equal to the number of bins. If `errors` is absent, no per-bin uncertainty is associated with the sample. This `data` is the template of the sample, i.e. the predicted yields and their uncertainties, not observed data. 
    -   `modifiers`: array of structs with each struct containing the modifiers for this sample.
    Struct of one modifier:
        -  `name`: ([optional]{.smallcaps}) custom string, unique within this sample. [required]{.smallcaps} for `custom` modifiers, where it names a function defined in the top-level component `functions`.
        -  `type`: type of the modifier
        -  `parameters`: array of strings naming the parameters controlling this modifier.
        -  `data`: [optional]{.smallcaps} relevant data for modifier. Its format depends on `type`, which is described above.
        -  `constraints`: [optional]{.smallcaps} array of distribution names, with one entry for each parameter in `parameters`. Individual entries [may]{.smallcaps} be `null`, leaving the corresponding parameter unconstrained. 
        -  `interpolation`: [optional]{.smallcaps} struct defining how the effect of the modifier is calculated within and outside of the boundaries $\theta=\pm 1$. It has the components `type`, `in` and `out` as described above. If this is omitted here for at least one modifier the top-level component `default_interpolation` becomes [required]{.smallcaps}. Implementations [must not]{.smallcaps} assume a default interpolation of their own; a document in which a modifier omits `interpolation` and no `default_interpolation` is given is invalid and [must]{.smallcaps} be rejected.

For modifiers controlling a single parameter (`histosys`, `normsys`, `normfactor`), the arrays `parameters` and `constraints` hold a single entry each. 

Two modifiers are correlated if and only if they share the same parameters as indicated by `parameters`. In such a case, they [must]{.smallcaps} share the same constraint term in `constraints`. By the rule above, that term is counted once. 

```json title="HistFactory"
{
  "name": "myAnalysisChannel",
  "type": "histfactory_dist",
  "axes": [ 
	{ "max": 1.0, "min": 0.0, "name": "myRegion", "nbins": 2 } 
  ],
  "default_interpolation": { "type": "mult", "in": "poly6", "out": "exp" },
  "samples": [
    { 
      "name": "mySignal",
      "data": { "contents": [ 0.5, 0.7 ], "errors": [ 0.1, 0.1 ] },
      "modifiers": [
        { "parameters": ["Lumi"], "type": "normfactor" },
        { "parameters": ["mu_signal_strength"], "type": "normfactor" },
        { "constraints": ["my_normalization_systematic_1_constraint"], 
          "data": { "hi": 1.1, "lo": 0.9 }, 
          "parameters": ["my_normalization_systematic_1"], 
          "type": "normsys" },
        { "constraints": ["gamma_stat_constraints", "gamma_stat_constraints"], "type": "staterror", 
          "parameters": ["gamma_stat_1","gamma_stat_2"]},
        { "constraints": ["my_correlated_shape_systematic_1_constraint"], "type": "histosys", 
          "data": { 
            "hi": { "contents": [ -2.5, -3.1 ] }, 
            "lo": { "contents": [ 2.2, 3.7 ] } 
           }, 
           "interpolation": { "type": "add", "in": "poly6", "out": "poly1" },
           "parameters": ["my_correlated_shape_systematic_1"] },
        { "constraints": ["my_shapesys_2_bin0_constraint", "my_shapesys_2_bin1_constraint"],
          "parameters": ["my_uncorrelated_shape_systematic_2_bin0", "my_uncorrelated_shape_systematic_2_bin1"], 
          "type": "shapefactor" }
      ]
    },
    { 
      "name": "myBackground",
      ... 
   }
  ]
} 
```


The `staterror` constraint named above is a single array, defined as one entry of the top-level `distributions`, with its global observables as an entry of `data`. For illustration, assuming that `mySignal` is the only sample, so that $\delta_i=\sigma_{s,i}/y_{s,i}$:

```json title="Constraint of the staterror modifier"
{
  "distributions": [
    {
      "name": "gamma_stat_constraints",
      "type": "array_dist",
      "component_type": "gaussian_dist",
      "components": [
        { "x": "nom_gamma_stat_1", "mean": "gamma_stat_1", "sigma": 0.2 },
        { "x": "nom_gamma_stat_2", "mean": "gamma_stat_2", "sigma": 0.143 }
      ]
    }
  ],
  "data": [
    {
      "name": "global_observables_stat",
      "type": "unbinned",
      "entries": [[1.0, 1.0]],
      "axes": [
        { "name": "nom_gamma_stat_1", "min": 0.0, "max": 5.0 },
        { "name": "nom_gamma_stat_2", "min": 0.0, "max": 5.0 }
      ]
    }
  ]
}
```
