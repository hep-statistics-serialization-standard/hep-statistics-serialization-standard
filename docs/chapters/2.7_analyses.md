## Analyses {#sec:analyses} 
The top-level component `analyses` contains an array of possible (automated) analyses. To that extent, likelihoods, parameters of interest and the affiliated domains are listed. Description of the components: 

- `name`: long custom string 
- `likelihood`: name as reference to a likelihood defined in the top-level component `likelihoods`. This [may]{.smallcaps} be a pure model (see [Pure models](#sec:likelihood-pure-model){reference-type="ref" reference="sec:likelihood-pure-model"}). What can be done with such an analysis, for example the generation of toy data, is at the discretion of the implementation; anything that evaluates the likelihood requires data to be supplied first. 
- `parameters_of_interest`: ([optional]{.smallcaps}) array of names as reference to parameters that are interesting for the analysis at hand 
- `domains`: array of names of domains to be used for the parameters, defined in the top-level component `domains`. The effective domain of the analysis is the Cartesian product of the listed domains. If two of the listed domains contain an axis with the same name, the document is invalid. 
- `init`: ([optional]{.smallcaps}) name of an initial value to be used, defined in the top-level component `parameter_points` 
- `prior`: ([optional]{.smallcaps}) name of a prior distribution, defined in the top-level component `distributions`. This is only used for Bayesian interpretations and should not be confused with auxiliary distributions listed in the likelihood section. The prior could, for example, be a product distribution of all the individual priors. If for any parameter, both a prior and a parameter domain are given, the prior should be truncated to the given parameter domain. For a parameter that the prior does not cover, which is every parameter if `prior` is absent, a Bayesian interpretation assumes an implicit flat prior over the given parameter domain. 

All parameters of all distributions in the likelihood must either be listed in one of the domains referenced, or set to `const` in the parameter point referenced. This includes the names in the variate components of distributions without paired data (see [Likelihoods](#sec:likelihoods){reference-type="ref" reference="sec:likelihoods"}), and it applies to pure models as well. 

```json title="Example: Analyses"
"analyses": [ 
  { 
    "name" : "analysis1", 
    "likelihood" : "likelihood1", 
    "parameters_of_interest" : ["param1"], 
    "domains" : ["domain1"], 
    "init" : "starting_values", 
    "prior" : "prior_dist" 
  }, 
  ... 
]
```
