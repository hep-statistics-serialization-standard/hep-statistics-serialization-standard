## Likelihoods {#sec:likelihoods} 
The top-level component `likelihoods` contains an array of likelihoods in struct format specifying mappings of distributions and observations. The corresponding distributions and observations are inserted as keys in string format referencing to distributions and observations defined in the respective top-level components, or as numbers for fixed data values. 
The combination of parameterized distributions $m_i(\theta_i)$ with observations $x_i$ generates a likelihood function 



$$
\begin{aligned} \ensuremath{\mathscr{L}}(\theta_1, \theta_2, \ldots) &=  \prod_i \text{PDF}(m_i(\theta_i), x_i) \end{aligned} 
$$



The components of a likelihood struct are: 

-   `name`: custom string 
-   `distributions`: array of strings referencing the considered     distributions 
-   `data`: array of strings referencing the used data, must be of the     same length as the array of `distributions`. Alternatively, the     data-values for single-dimensional distributions can be given     in-line. For example, this can be used for constraint terms     representing auxiliary measurements. 
-   `aux_distributions`: ([optional]{.smallcaps}) array of strings     referencing the considered auxiliary distributions defined in the     top-level component `distributions`. They can be used to encode     regularizers or penalty terms to aid the minimization. These     observed data for these distributions is implicit and not part of     `data`. 

```json title="Example: Likelihoods"
"likelihoods":[ 
  { 
    "name":"likelihood1", 
    "distributions":[ 
      "dist1", 
      "dist2", 
      "single_dimensional_dist_1", 
      ... 
    ], 
    "data":         [ 
      "data1", 
      "data2", 
      0, 
      ... 
    ], 
    "aux_distributions" : [ "regularization_term" ] 
  }, 
  ... 
] 
``` 
### Auxiliary measurements and global observables
*This section is non-normative.* 


Nuisance parameters are commonly constrained by auxiliary measurements: supplemental likelihood terms (often unit Gaussians) whose observed values (sometimes known as *global observables*) can be fixed and are generally not part of the primary data.
The mechanisms described in [Likelihoods](#sec:likelihoods){reference-type="ref" reference="sec:likelihoods"} can already accommodate such terms in several ways.

One way, though not the recommended one (see below), is to fold the constraint terms into a [Product distribution](#sec:product-distribution){reference-type="ref" reference="sec:product-distribution"} together with the channel distribution, with the global observables as constant parameters:

```json title="Example: Auxiliary measurements as factors of a product distribution"
{
  ...
  "distributions":[
    {
      "name":"model",
      "type":"product_dist",
      "factors":["channel1_pdf","gauss_constraint_alpha_1","gauss_constraint_alpha_2","gauss_constraint_alpha_3"]
    },
    {
      "name":"gauss_constraint_alpha_1",
      "type":"gaussian_dist",
      "x":"nom_alpha_1",
      "sigma":1.0,
      "mean":"alpha_1"
    },
    {
      "name":"gauss_constraint_alpha_2",
      "type":"gaussian_dist",
      "x":"nom_alpha_2",
      "sigma":1.0,
      "mean":"alpha_2"
    },
    {
      "name":"gauss_constraint_alpha_3",
      "type":"gaussian_dist",
      "x":"nom_alpha_3",
      "sigma":1.0,
      "mean":"alpha_3"
    },
    ...
  ],
  ...
  "parameter_points":[
    {
      "name":"default_values",
      "parameters":[
        {"name":"nom_alpha_1", "value":0.0, "const":true},
        {"name":"nom_alpha_2", "value":0.0, "const":true},
        {"name":"nom_alpha_3", "value":0.0, "const":true},
        ...
      ]
    }
  ],
  "likelihoods":[
    {
      "name":"likelihood1",
      "distributions":["model"],
      "data":["channel1_data"]
    }
  ]
}
```

Alternatively, each constraint distribution can enter the likelihood directly, paired with a point data set:

```json title="Example: Auxiliary measurements as constraint distributions paired with point datasets"
{
  ...
  "distributions":[
    {
      "name":"gauss_constraint_alpha_1",
      "type":"gaussian_dist",
      "x":"nom_alpha_1",
      "sigma":1.0,
      "mean":"alpha_1"
    },
    {
      "name":"gauss_constraint_alpha_2",
      "type":"gaussian_dist",
      "x":"nom_alpha_2",
      "sigma":1.0,
      "mean":"alpha_2"
    },
    {
      "name":"gauss_constraint_alpha_3",
      "type":"gaussian_dist",
      "x":"nom_alpha_3",
      "sigma":1.0,
      "mean":"alpha_3"
    },
    ...
  ],
  "data":[
    {
      "name":"obs_nom_alpha_1",
      "type":"point",
      "value":0.0,
      "axes":[{"name":"nom_alpha_1","min":-5,"max":5}]
    },
    {
      "name":"obs_nom_alpha_2",
      "type":"point",
      "value":0.0,
      "axes":[{"name":"nom_alpha_2","min":-5,"max":5}]
    },
    {
      "name":"obs_nom_alpha_3",
      "type":"point",
      "value":0.0,
      "axes":[{"name":"nom_alpha_3","min":-5,"max":5}]
    },
    ...
  ],
  "likelihoods":[
    {
      "name":"likelihood1",
      "distributions":["channel1_pdf","gauss_constraint_alpha_1","gauss_constraint_alpha_2","gauss_constraint_alpha_3"],
      "data":["channel1_data","obs_nom_alpha_1","obs_nom_alpha_2","obs_nom_alpha_3"]
    }
  ]
}
```

For models with many constraints, listing one term per constrained parameter in either form becomes lengthy. 
When the constraint terms are independent and of the same kind (e.g. unit Gaussians or Poisson terms) they can instead be collected into a single pair: an `unbinned` data set with a categorical axis enumerating the constrained parameters, holding one entry per auxiliary measurement, paired with a [Diagonal distribution](#sec:diag-distribution){reference-type="ref" reference="sec:diag-distribution"} that evaluates one constraint term per entry:

```json title="Example: Auxiliary measurements as a diagonal constraint"
{
  ...
  "distributions":[
    {
      "name":"gauss_constraints",
      "type":"diagonal_dist",
      "of":"gaussian_dist",
      "category_index":"np",
      "x":"gauss_constraints_x",
      "default_parameters":{"sigma":1.0},
      "dimensions":[
        {"category":"nom_alpha_1","parameters":{"mean":"alpha_1"}},
        {"category":"nom_alpha_2","parameters":{"mean":"alpha_2"}}
        {"category":"nom_alpha_3","parameters":{"mean":"alpha_3"}}
      ]
    },
    ...
  ],
  "data":[
    {
      "name":"global_observables",
      "type":"unbinned",
      "entries":[ ["nom_alpha_1",0.0], ["nom_alpha_2",0.0], ["nom_alpha_3", 0.0]],
      "axes":[
        {"name":"np","categories":["nom_alpha_1","nom_alpha_2","nom_alpha_3"]},
        {"name":"gauss_constraints_x", "min":-5, "max":5}
      ]
    },
    ...
  ],
  "likelihoods":[
    {
      "name":"likelihood1",
      "distributions":["channel1_pdf","gauss_constraints"],
      "data":["channel1_data", "global_observables"]
    }
  ]
}
```

Since every entry of an unbinned data set contributes exactly one factor to the likelihood, each constraint term enters exactly once. Encoding constraint terms as a diagonal distribution paired with an unbinned data set is recommended over listing individual pairs as described above, and in particular over folding them into per-channel [Product distributions](#sec:product-distribution){reference-type="ref" reference="sec:product-distribution"} as factors that do not depend on the primary observables, where the intended multiplicity of these factors in the likelihood is ambiguous.
